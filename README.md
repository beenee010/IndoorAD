# AirGuard 공기질 관리 대시보드

아두이노의 공기질 측정 기록을 분석하고 실시간 데이터를 수신하는 로컬 웹 프로그램임.
Node.js 내장 SQLite로 데이터를 저장하며 별도 npm 패키지 설치 없이 실행 가능함.

## 주요 기능

- CSV 검증과 업로드 및 중복 처리 지원함.
- 측정 추이와 원시 기록 및 센서 품질 상태를 제공함.
- 실시간 수신과 경고 규칙 설정 및 경고 확인을 지원함.
- 브라우저 경고음과 아두이노 부저 명령 API를 제공함.
- 에어코리아 관측값을 외부 참고 정보로 조회함.

## 실행

Node.js 22.13 이상이 필요함. 개발 및 검증 환경은 Node.js 26.10임.

```bash
npm start
```

[대시보드 접속 주소](http://127.0.0.1:4173)는 위 명령 실행 후 사용 가능함.
`index.html`을 직접 여는 방식은 서버 API와 연동되지 않음.

기본 장치 ID는 `lab-01`이며 새 데이터베이스에는 측정 기록이 없는 상태임.
데이터 가져오기 메뉴에서 CSV를 선택한 뒤 검증 결과를 확인하고 저장함.
저장된 데이터는 `data/` 폴더에 유지되므로 서버 재시작 후에도 조회 가능함.
서버 종료는 실행 중인 터미널에서 `Ctrl+C`로 수행함.

### 초기 CSV 가져오기

빈 데이터베이스에 초기 기록을 넣으려면 CSV의 절대 경로를 지정함.

```bash
SEED_CSV='/절대경로/air_log.csv' npm start
```

초기 가져오기는 데이터베이스에 측정 기록이 없을 때만 수행함.
과거 CSV는 기록 분석용으로 저장하며 현재 경고음이나 부저 명령을 발생시키지 않음.

## 대시보드

실시간 현황과 기록 분석 및 경고 이력을 조회할 수 있음.
장치와 조회 기간을 선택하면 해당 범위의 지표와 차트를 표시함.

| 항목 | 표시 및 처리 방식 |
| --- | --- |
| PM2.5 | 초미세먼지 농도를 µg/m³ 단위로 표시함. |
| CO₂ | ppm 단위로 표시하며 실측인지 eCO₂인지 센서 사양 확인이 필요함. |
| DHT 온습도 | 기본 대표 온도와 상대습도로 표시함. |
| AM 온습도 | DHT와 분리된 보조 센서 값으로 표시함. |
| VOC | 원시 단계로 표시하며 의미 확인 전 농도 단위를 부여하지 않음. |

차트에는 측정 시각과 단위 및 집계 구간을 표시하고 긴 수집 공백은 선으로 연결하지 않음.
결측과 미지원 항목은 0으로 대체하지 않음.

기록 분석은 마지막 측정 시각을 기준으로 조회함.
실시간 모드는 측정 시각과 수신 시각을 구분해 지연 상태를 표시함.
경고 판정에는 센서 검증 상태와 읽기 성공 여부 및 조건 지속시간을 함께 적용함.

### 경고 규칙 변경 검토

설정에서 규칙 값을 바꾼 뒤 변경 검토를 누르면 변경 전후 값을 비교할 수 있음. 사유를 입력하고 적용하면 규칙 버전이 올라가며 이전 버전과 변경 시각 및 사유가 변경 이력에 남음. 같은 규칙이 먼저 변경됐다면 최신 버전으로 다시 검토해야 함.

변경 이력은 SQLite에 추가 전용으로 기록하고 SHA-256 연결과 현재 규칙의 일치 여부를 확인함. 기존 규칙은 첫 변경의 기준 버전으로 사용함. 무결성 표시는 이 컴퓨터의 저장 기록을 검사한 결과임.

데이터 가져오기 이력에서 시간대와 저장 및 중복·충돌·오류 건수와 UTF-8 입력의 SHA-256을 확인할 수 있음.

## 실시간 수신

서버 설정은 `.env` 파일 또는 실행 환경변수로 관리함.
설정 항목은 [.env.example](.env.example)을 참고함.

| 환경변수 | 용도 |
| --- | --- |
| `PORT` | 서버 포트이며 기본값은 `4173`임. |
| `AIRGUARD_DEVICE_TOKEN` | 실시간 수신과 부저 명령 API 인증에 사용하는 토큰임. |
| `AIRGUARD_DEVICE_ID` | 토큰에 연결할 장치 ID이며 기본값은 `lab-01`임. |
| `AIRKOREA_SERVICE_KEY` | 에어코리아 조회에 사용하는 서버 인증키임. |
| `SEED_CSV` | 빈 데이터베이스에 가져올 초기 CSV의 절대 경로임. |

장치 토큰은 충분히 긴 임의 문자열로 설정하며 브라우저에 노출하지 않음.

### 측정값 전송 API

```text
POST /api/v1/measurements/batch
Authorization: Bearer <AIRGUARD_DEVICE_TOKEN>
Content-Type: application/json
```

```json
{
  "schema_version": "1.0",
  "device_id": "lab-01",
  "batch_id": "device-boot-001-batch-001",
  "samples": [{
    "sample_id": "device-boot-001-sample-001",
    "measured_at": "2026-10-14T15:00:00+09:00",
    "metrics": {
      "dht_temp_C": 22.3,
      "dht_humi_pct": 51.0,
      "am_temp_C": null,
      "am_humi_pct": null,
      "co2_ppm": 900,
      "voc_level": 0,
      "pm25_ugm3": 5
    },
    "read_status": {"dht": "ok", "am": "error", "air": "ok"}
  }]
}
```

위 JSON은 전송 형식 예시임. 실제 전송 시 측정값과 시각 및 식별자를 갱신해야 함.
읽기 실패 채널은 `null`과 `error`로 전송하며 마지막 정상값을 반복하지 않음.
센서 사양과 정상 동작을 확인한 뒤 장치 설정에서 검증 상태를 활성화함.

### 기존 CSV 로거 연결

기존 프로그램이 CSV에 측정 행을 추가하는 경우 아래 수집 스크립트로 연결 가능함.
Python 표준 라이브러리만 사용하며 별도 패키지 설치가 필요하지 않음.

게이트웨이는 `.env`를 자동으로 읽지 않으므로 실행 환경에 서버와 동일한 토큰을 설정해야 함.

```bash
export AIRGUARD_DEVICE_TOKEN='서버와_동일한_토큰'
python3 scripts/csv_gateway.py '/절대경로/air_log.csv' --follow --device lab-01
```

`--follow`는 기존 행을 건너뛰고 새 행만 읽어 최대 100건씩 전송함.
네트워크 장애 시 동일한 배치 ID로 재시도하며 원본 CSV는 변경하지 않음.
프로그램 종료나 로거 파일 교체 후에는 게이트웨이를 다시 실행해야 함.
누락된 과거 구간은 CSV 가져오기로 보충 가능함.

CSV에는 센서 읽기 성공 정보가 없어 이 경로의 데이터 품질은 미확인으로 표시함.
규칙 경고를 사용하려면 센서 검증과 함께 펌웨어 또는 수집 코드에서 `read_status`를 제공해야 함.

### 아두이노 부저 연결

장치 설정의 부저 연결됨 옵션을 활성화한 경우 새 실시간 경고에 대한 명령을 생성함.
실제 부저 작동에는 아래 API를 처리하는 장치 펌웨어가 필요함.

| API | 역할 |
| --- | --- |
| `GET /api/v1/devices/{id}/commands` | 인증된 장치의 대기 명령을 조회함. |
| `POST /api/v1/commands/{id}/ack` | 실행 결과를 `executed` 또는 `failed` 상태로 회신함. |

명령은 30초 후 만료되며 재연결 시 오래된 명령을 실행하지 않음.

## 외부 대기질

공공데이터포털의 [에어코리아 대기오염정보 API](https://www.data.go.kr/data/15073861/openapi.do) 활용 신청 후 인증키를 서버에 설정함.

```text
AIRKOREA_SERVICE_KEY=발급받은_디코딩_인증키
```

장치 설정의 외부 측정소 항목에 실제 측정소 이름을 입력함.
외부 관측값은 실내 센서와 구분해 표시하며 과거 CSV에 현재 외부값을 연결하지 않음.
외부 API가 미설정이거나 조회에 실패해도 실내 측정과 기록 분석은 사용 가능함.
위도와 경도는 설치 장소 정보로 저장 가능하며 자동 근접 측정소 선택은 후속 구현 항목임.

## 로컬 운영 범위

현재는 단일 로컬 관리자가 사용하는 구성임.
서버는 `127.0.0.1`에서 실행되며 USB 수집 에이전트는 같은 컴퓨터에서 연결 가능함.
ESP32가 Wi-Fi로 직접 접속하려면 인증을 갖춘 네트워크 배포가 필요함.
`data/`와 `.env`는 정적 웹 경로로 제공하지 않음.

아래 항목은 후속 구현 범위임.

- 로그인과 사용자별 접근 권한
- AI 모델 학습과 예측 경고
- 자동 근접 측정소 선택
- 외부 호스팅과 메시지 발송 및 자동 청정기 제어
- 데이터 보관 만료와 자동 삭제

## 검증

```bash
npm run check
npm test
python3 scripts/test_csv_gateway.py
```

문법 검사와 데이터 처리 및 API 테스트를 위 명령으로 수행함.
게이트웨이 테스트는 Python 실행 환경이 필요함.
